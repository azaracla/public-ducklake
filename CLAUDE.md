## Project overview

Public DuckLake is a DuckDB/DuckLake catalog exposing French public datasets from data.gouv.fr as SQL-queryable tables. Users attach the catalog over HTTP and query remote Parquet files with zero download, no ETL, no server.

The key artifact is `data_gouv_catalog.ducklake` — a ~11MB binary catalog file referencing remote Parquet files on `static.data.gouv.fr` and `data.education.gouv.fr`. It is hosted on GitHub's raw CDN so users can `ATTACH` it directly:

```sql
ATTACH 'ducklake:https://raw.githubusercontent.com/azaracla/public-ducklake/main/data_gouv_catalog.ducklake' AS dg (TYPE ducklake, READ_ONLY true);
```

## Architecture

### Catalog generation

The `.ducklake` file is generated by running `scripts/generate_ducklake.sql` in DuckDB:

```bash
duckdb data_gouv_catalog.ducklake < scripts/generate_ducklake.sql
```

This script:
1. Installs and loads `ducklake` and `httpfs` extensions
2. Attaches `data_gouv_catalog.ducklake` with `DATA_PATH './dg_lake/'` (local metadata storage)
3. Creates schemas and includes individual table definition files from `schemas/v2026-06-03/`

### Schema versioning

Table definitions live under `schemas/<version>/<schema>/<table>.sql`. Each file:
- `CREATE TABLE` with all columns (all NULLable, matching source)
- Optional `COMMENT ON TABLE` and `COMMENT ON COLUMN` for documentation
- `CALL ducklake_add_data_files(...)` — registers a remote Parquet URL for the table

Version is date-based (e.g., `v2026-06-03`). Point `generate_ducklake.sql` at the latest version.

### Dataset tracking

`tracking/datasets.json` — JSON registry mapping data.gouv.fr dataset IDs to their category, tables, Parquet URLs, last update date, and schema version. `references/datasets.md` is the human-readable equivalent.

### Python project

`pyproject.toml` defines dependencies (`geoarrow-pyarrow`, `geopandas`, `pyarrow`, `shapely`) used for GeoParquet transformation scripts. `main.py` is a placeholder.

## CI validation

CI (`.github/workflows/ci.yml`) runs on push/PR to `main`:
- Installs DuckDB, ducklake, and httpfs
- Lists all catalog tables
- Runs `COUNT(*)` on every table with per-table error isolation
- Validates cross-schema queries (education × demographie)
- Validates column comments on `foncier.dvf`

## Key data caveats

- **`force_download=true` FORBIDDEN**: this DuckDB config (`BOOLEAN`, default `false`) forces full file download instead of HTTP range requests. It breaks DuckLake lazy loading, destroys performance, and triggers `stoi` errors on some Parquet files. Never use it with the DuckLake catalog.
- **Non-numeric values in numeric columns**: `education.ips_ecoles.ips` and `education.indice_eloignement_lycees.indice_eloignement` contain strings like `'NS'`, `'NA'`. Filter with `~ '^[0-9]+(\.[0-9]+)?$'` before casting.
- **Region name normalization**: Tables use different region naming conventions. Normalize with `UPPER(TRIM())` for cross-schema joins.
- **Entreprise region linkage**: Sirene tables use `libelleCommune2Etablissement` (commune name), not region codes. BEAAMP uses `region_acheteur`.
- **Foncier geometry**: `foncier.dvf` uses GeoParquet v2 with a native `geom GEOMETRY` column. Requires DuckDB `spatial` extension for spatial queries.
- **All columns NULLable**: Schema definitions mark every column `NULL` — the remote Parquet sources have no NOT NULL constraints.

## Non-Parquet data ingestion (JSON, CSV)

DuckLake `ducklake_add_data_files` only works with Parquet (`file_format` = `parquet`). For JSON/CSV sources:
1. **Parquet sources** → `CALL ducklake_add_data_files(...)` — registers remote file, zero-copy, lazy loading
2. **JSON/CSV sources** → Convert to Parquet first with Python/pyarrow, then `ducklake_add_data_files`

DuckDB can natively read JSON but nested JSON (non-NDJSON) like DECP `{marches: {marche: [...]}}` requires O(n) memory to flatten — a 50MB JSON file consumed 9.3GB RAM. NDJSON (`format='newline_delimited'`) should work but data.gouv.fr publishes mostly nested JSON for large datasets.

**Conversion workflow tested:**
```python
import json, pyarrow as pa, pyarrow.parquet as pq
with open('source.json') as f:
    data = json.load(f)
rows = [flatten_record(m) for m in data['marches']['marche']]
pq.write_table(pa.Table.from_pylist(rows), 'output.parquet', compression='zstd')
```
Result: 49.9MB JSON → 1.4MB Parquet (35x compression, 26K rows in one month).
